# KXC-01 local radial ALSDA transverse kernel

## Status and claim level

The direct local transverse ALSDA kernel is implemented in
[`source/lr_alsda_kernel.f90`](../source/lr_alsda_kernel.f90) and registered in
the `rslmto` library.  This is an algebraic and independent numerical
cross-check of the LR-03 mapped kernel in the LR-04 response space.  It is not
a Goldstone correction, a sum-rule interaction, a material validation, or a
literature-spectrum agreement claim.

The implementation supports the explicitly controlled initial approximation
selected by LR-03:

\[
 K_{xc}^{P\leftarrow SR}(r)=
 \frac{B_{xc}^{\sigma,SR}(r)}{s^P(r)},
 \qquad
 B_{xc}^{\sigma,SR}(r)=
 \frac{V_{xc,\uparrow}(r)-V_{xc,\downarrow}(r)}{2}.
\]

Here `s^P` is the Pauli/no-SOC response magnetization supplied by the accepted
Pauli ground-state closure.  It is deliberately not silently replaced by the
scalar-relativistic LR-01 `n_up-n_down`; the LR-01 XC field and the Pauli
response magnetization remain visibly separate.  For `g=2`, this is exactly
the LR-03 mapping of the BES relation, with no additional `mu_B`, factor of
two, or sign change.

## Source contracts and API

The request type is `lr_alsda_kernel_request` in
`lr_alsda_kernel_mod`:

```fortran
type(lr_alsda_kernel_request) :: request
type(lr_alsda_kernel_result) :: result

request%response_space => space
request%ground_states => accepted_radial_states
request%pauli_magnetization = pauli_m
request%magnetization_label = lr_kxc_magnetization_pauli
request%requested_functional = 'Barth-Hedin'
request%requested_backend = 'legacy RS-LMTO'
request%requested_txc = 1
call evaluate_lr_alsda_kernel(request, result)
```

`ground_states(site)` must be a valid and accepted LR-01 snapshot.  The
snapshot is the only source of `Vxc_up` and `Vxc_down`; no compressed LMTO
potential, boundary value, or reconstructed field is used.  The request
requires `pauli_magnetization(site,radial_point)` explicitly and labels it
`pauli_projected`.  A different label is rejected rather than silently
selecting the SR density.

The result contains:

* `pointwise_kernel(site,radial_point)`, in `Ry bohr^3`;
* `canonical_operator`, the LR-04 local operator;
* copied XC provenance from the accepted snapshots; and
* the active-grid low-m diagnostic.

The accepted XC provenance is checked for every response site.  The functional
name, backend, TXC, XC route metadata, energy units, and component metadata
must agree between sites.  Optional requested functional/backend/TXC fields are
exact constraints; a mismatch terminates the evaluator with an explicit
error.  Blank optional request fields mean the accepted snapshot provenance is
used as-is, not that provenance checking is skipped.

## Discretization and operator representation

For the LR-01 logarithmic mesh,

\[
 r_i=B[\exp(A(i-1))-1],
 \qquad
 W_i=s_i r_i^2 A(r_i+B),
\]

where `s_i` is the established Simpson coefficient.  LR-04 stores a local
pointwise multiplication operator directly in its canonical representation:

\[
 (Kx)_{aLMi\mu}=K_a(r_i)x_{aLMi\mu},
 \qquad
 B^K_{IJ}=\delta_{IJ}K_a(r_i).
\]

The implementation therefore delegates construction to
`response_local_operator`.  It does not invent a Dirac-delta `1/W` factor and
does not insert an extra radial measure into the matrix action.  The resulting
operator is diagonal in site, `L`, `M`, radial point, and channel.  No angular
quadrature or site-only reduction is introduced.

The origin is an exact null-measure point in LR-04.  If `s^P(0)` is exactly
zero, the kernel stores the zero null-space extension at that point and reports
`origin_null_measure_extension`; this value cannot affect a response
contraction.  A zero `s^P` at any positive-measure radial point is rejected as
`BLOCKED`.  No epsilon floor, clipping, spline replacement, or radial cutoff
is used.

## Provenance and units

The numerator is an energy-valued Pauli coefficient in Ry, not a physical
magnetic field in tesla:

\[
 B_{xc}^{\sigma}=\Delta V_{xc}/2.
\]

The denominator is the Pauli number-spin density in electrons bohr`^-3`.
Consequently `K_xc` has units `Ry bohr^3` (with the electron-number unit
understood).  `B_fsm` and total KS spin splitting are not used in the direct
kernel; only the exact stored XC arrays enter.

The response result carries the accepted `radial_xc_provenance`.  In
particular, the implementation cannot request a different functional from the
one that generated the accepted radial state.  This protects against silently
using a convenient LSDA expression for a ground state generated by another
route.

## Low-m diagnostic

Every radial point with positive LR-04 measure is inspected.  The diagnostic
reports the number of active points, the minimum and maximum absolute `s^P`,
the minimum relative magnitude, and the count below the explicitly requested
diagnostic threshold.  The threshold is diagnostic only and never changes the
ratio.  A small but nonzero denominator is evaluated exactly; an exact zero on
the active grid is a capability blocker.  Thus a large kernel value is visible
evidence of the input magnetization scale rather than a hidden regularization.

## Raw static Goldstone/Ward diagnostic

`evaluate_lr_alsda_static_residual` takes an unmodified LR-06 static `chiKS`,
the canonical direct kernel, and an independently supplied rigid vector.  It
forms

\[
 b_{xc}=K_{xc}g,
 \qquad
 r=\chi^{KS}(0,0)b_{xc}-g,
\]

and reports the LR-04 metric norm, relative norm, and rigid-vector overlap.
The optional residual vector is available for radial/angular distribution
diagnostics.  The overlap is the metric overlap of the residual with the
rigid vector.  This is a raw diagnostic only: it does not rescale `Kxc`, change
`chiKS`, shift an eigenvalue, or enforce Goldstone behavior.  The focused
synthetic fixture gives:

```text
KXC raw static residual (absolute, relative) = 1.89595018E-02 8.61697876E-01
KXC rigid-vector overlap (real, imag) = -4.17128621E-04 0.00000000E+00
```

The nonzero value is retained for later GSR/GCR analysis and does not fail
KXC-01.

## Tests and evidence

`UnitLrAlsdaKernel` is a standalone Fortran test registered with CTest.  It
checks:

* exact pointwise reconstruction from independent `Vxc_up/down` and `s^P`;
* `Ry bohr^3` units and LR-04 representation metadata;
* local operator action against an independent explicit nested-loop oracle;
* site/`L`/`M`/radial/channel diagonal structure;
* global spin reversal, with both XC channels and `s^P` reversed;
* an active-grid low-`m` point evaluated without a floor or clipping;
* raw static residual and metric overlap reporting; and
* negative provenance checking through a separate expected-failure CTest case.

The focused verification was:

```text
cmake --build build --target UnitLrAlsdaKernel -j2
ctest --test-dir build --output-on-failure -R '^UnitLrAlsdaKernel($|RejectProvenance$)'
```

Result: both tests passed (2/2).  The positive executable reported zero
pointwise reconstruction, local-action, and spin-reversal errors.  These are
algebraic and independent numerical-oracle claims, not converged Fe/Ni or
literature validation.

## Scope boundary

This task adds only the direct local ALSDA kernel and its raw diagnostic.  It
does not implement the Lounis sum-rule interaction, Goldstone correction,
Dyson equation, loss matrix, mode extraction, empirical rescaling, exact
scalar-relativistic response, or an exact Pauli-functional ground state.
