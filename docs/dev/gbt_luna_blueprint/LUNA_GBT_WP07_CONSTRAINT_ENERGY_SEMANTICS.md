# Luna Prompt — GBT-WP07: Constraining-Field Energy Semantics

## Mission

Determine exactly what the current constraint routine returns as `constraint_energy`, whether it is a physical constrained-DFT energy contribution or a numerical penalty/controller merit term, and repair reporting/bookkeeping so frozen-magnon and SCF energy differences have an unambiguous physical meaning.

Do not guess from variable names.

## Dependency

WP06 must establish a working, nonzero constraining-field case.

## Required formal audit

Read the complete constraint update implementation and derive from code the mathematical functional being represented.

Identify separately:

1. physical DFT total energy of the state;
2. auxiliary Kohn-Sham term generated by the constraining field;
3. Lagrange-multiplier constraint functional, if represented;
4. numerical penalty or PID/controller merit function;
5. any double-counting correction required if field terms appear in eigenvalue sums.

Cross-check the interpretation against constrained-magnetism literature, especially Dederichs-type constrained DFT, Bruno's renormalized-force-theorem discussion, and the ELK/Jacobsson workflow.

## Current behavior to challenge explicitly

The current SCF path adds `constraint_energy` to the sum of atomic potential energies when reporting/storing the total energy.

Do **not** preserve this merely for backward compatibility if the derivation shows it is not the physical energy.

At the same time, do not remove it blindly. First identify its exact meaning.

## Required numerical invariance experiment

Using a converged nonzero-field fixture from WP06:

- vary controller gain/penalty parameters over a sensible stable range;
- converge to the same prescribed physical moment directions;
- compare the candidate physical energy.

The physical energy difference should be invariant within numerical convergence tolerance.

If the reported “total energy” changes materially with controller tuning after the same constrained state is reached, that quantity contains algorithmic penalty energy and must not be used as the physical frozen-spiral energy.

## Required output/API cleanup

Expose separate quantities with unambiguous names. Exact names may follow project style, but conceptually distinguish:

- physical total energy;
- constraint-field/Lagrange diagnostic contribution if meaningful;
- numerical constraint penalty/controller energy;
- auxiliary total used internally if one exists.

Preserve compatibility where practical, but prioritize correctness and explicit warnings over ambiguous legacy output.

## Band-energy / force-theorem bookkeeping

If a constraining field is included in one-shot eigenvalues, derive whether the desired corrected-MFT observable uses:

- raw eigenvalue sum;
- eigenvalue sum minus a field-coupling term;
- another double-counting correction.

Do not implement WP08 corrected MFT until this is resolved.

## Tests

Add tests for:

- zero constraint -> zero diagnostic contribution;
- converged same physical state under different controller settings -> same physical energy;
- any claimed Lagrange term -> correct behavior as constraint residual tends to zero;
- no accidental double addition in ordinary and GBT paths.

## Deliverables

- mathematical derivation in `docs/dev/GBT_REAUDIT_WP07_CONSTRAINT_ENERGY.md`;
- cleaned energy reporting/API;
- regression tests;
- migration note if historical output semantics change.
