## Executive verdict

The current GBT implementation is a primitive structure-constant implementation in the bulk Hamiltonian path:

```text
raw directed S(R), optionally Sdot(R)
        -> endpoint SU(2) link G(q,R)
        -> spinor/orbital lift
        -> ordinary LMTO contraction
        -> ee / eecc
        -> ordinary real-space or reciprocal assembly
```

It is not a post-hoc rotation of a final Hamiltonian. The old reciprocal GBT transform is absent, and `reciprocal_fourier.f90` performs ordinary Fourier assembly of the already gauged real-space blocks.

That architectural conclusion is established. Production readiness is not. The current tree has useful algebraic, operator-slice, lifecycle, Goldstone, and diagnostic evidence, but it does not establish all of the master blueprint’s required exact-operator, frame-contract, constrained-energy, fixed-potential, SCF, supercell, stiffness, and LKAG gates. In particular:

- the GBT bulk path is conditional: it rejects active SOC, `local_axis`, Hubbard-V, generalized-overlap modes, and non-bulk/local Hamiltonian use;
- `ee`/`eecc` are shared by the RS and k-space routes, but SCF moment feedback still has direct projected-DOS/eigenvector producers in addition to the shared rotating-frame density object;
- the current constraining-field machinery is active in the source, so the old WP6 matrix entry saying “inactive” is stale, but nonzero-q constrained-spiral covariance and energy semantics remain unvalidated;
- historical WP9/G9 remains failed or open; the current audit specifically retains the regenerated VAL-16 q=1/2 convergence failure and the VAL-17 fine-mesh stiffness gap;
- the historical reports demonstrate bounded slices, not a current production qualification.

### 1.2 Input and q conventions

`source/include_codes/namelists/hamiltonian.f90` and `source/hamiltonian_build.f90` define the current interface:

- `q_ss(3)` is a Cartesian q in units of `2*pi/alat`.
- A bond phase is `alpha = 2*pi*q_ss.dot(d_cart)/alat`.
- `theta_ss` is supplied in degrees and converted to radians internally.
- `magnetic_representation` is normalized to one of `periodic_nc`, `gbt_single_q`, or `explicit_texture`.
- A nonzero q is not silently accepted by `periodic_nc`; the source validation requires the GBT or explicit-texture representation.

The master blueprint’s working convention is consequently the one implemented by `gbt_endpoint_link`: for directed bond `i -> j`,

```text
Gij(q,R) = (Ua0)† diag(exp(-i alpha/2), exp(+i alpha/2)) Ub0
```

with `Ua0` and `Ub0` generated by `gbt_reference_frame`. This is consistent with the generalized-Bloch spinor convention used in the external spin-spiral literature. The official [ELK project site](https://elk.sourceforge.io/) documents spin-spiral support and should remain a convention cross-check, not a substitute for repository-level operator tests.

### 1.3 Evidence vocabulary

This report uses the following distinctions:

- **Implemented:** the current source has an executable route or guard for the feature.
- **Tested:** a named test, oracle, fixture, or report measured some part of that route.
- **Established:** the evidence closes the exact claim required by the master blueprint under the stated conditions.
- **Production-qualified:** all relevant exactness, operator, frame, solver, constraint, and physical validation gates have been met for the claimed scope.

Most historical GBT evidence reaches “tested” for a slice. Very little reaches “established” for the complete workflow, and none of this WP00 report upgrades a historical result to “production-qualified.”

## 2. A — current executable call graph

### 2.1 Top-level input and representation dispatch

```text
input file
  ├─ hamiltonian namelist: q_ss, theta_ss, representation, HOH, local_axis,
  │                         U/V, CCOR, SOC-related controls
  ├─ control namelist: nsp, calctype, density_policy
  ├─ reciprocal namelist: mesh, symmetry/q policy, DOS/backend
  └─ constraints/frozen_magnon namelists
        |
        v
control.f90
  ├─ reads and normalizes density policy and constraints
  ├─ sets nmdir from nsp
  └─ leaves the Hamiltonian representation to hamiltonian_build.f90
        |
        v
self%run / self%run_scf in self.f90
  ├─ initialize_constraint_state
  ├─ run_recursion
  ├─ run_dos
  ├─ mix charge/moment/density state
  ├─ apply_constraints
  ├─ rebuild potentials and evaluate total energy
  └─ iterate until the selected SCF condition is met
```

The Hamiltonian representation is selected in `build_bulkham`:

```text
build_bulkham
  ├─ periodic_nc
  │    └─ ordinary chbar_nc / onsite noncollinear path
  ├─ explicit_texture
  │    └─ validate per-site moments, then ordinary local-axis/noncollinear path
  └─ gbt_single_q
       └─ build_gbt_bulkham
            ├─ require lattice strux_lib backend
            ├─ reject unsupported GBT combinations
            ├─ read raw lattice%sbar(j,i,m,ino)
            ├─ calculate bond vector and endpoint frames
            ├─ build G(q,R) with gbt_endpoint_link
            ├─ lift scalar S to spinor/orbital blocks
            ├─ contract with collinear wx/cx endpoint factors
            ├─ store spherical ee blocks
            ├─ if CCOR: read raw Sdot and construct eecc with the same link
            └─ if HOH: build obarm/enim and derived eeo/eeoee diagnostics
```

`gbt_single_q` returns from `build_bulkham`, so it does not pass through the ordinary bulk contraction. Conversely, `build_locham` and `ham0m_nc` reject or bypass the GBT representation; the current GBT route is therefore a bulk `B/S/L` route, not a general local/impurity/surface route.

### 2.2 Hamiltonian terms and data products

```text
build_gbt_bulkham
  ├─ primitive two-centre S blocks -> ee
  ├─ optional Sdot blocks -> eecc
  ├─ onsite constraining field -> spin block in ee
  ├─ onsite/nonlocal U terms where allowed
  ├─ obarm and enim -> eeo = ee * obarm(target)
  └─ eeoee = eeo * ee† (stored diagnostic)
        |
        ├─ RS path (use_kspace = false)
        │    └─ recursion / Green functions / bands routines
        │
        └─ reciprocal path (use_kspace = true)
             └─ reciprocal_lifecycle
                  ├─ build/cache reciprocal mesh and k policy
                  ├─ reciprocal_fourier ordinary assembly of ee/eeo/eecc
                  ├─ add onsite enim/lsham/hcc
                  ├─ diagonalize H(k), and O(k) when enabled
                  ├─ canonical EF/EBAND and DOS
                  ├─ reciprocal spin-density accumulation
                  └─ direct spin-moment calculation for SCF feedback
```

There is no current `fourier_transform_gbt` implementation. The ordinary Fourier assembler applies the reciprocal phase to the already assembled directed blocks. HOH reciprocal assembly uses the Fourier-transformed `eeo` and `ee` product; `eeoee` is explicitly documented and treated as a same-bond diagnostic rather than a universal global contraction.

### 2.3 Density and SCF feedback

```text
RS: recursion -> Green functions
  ├─ calculate_magnetic_moments: projected-DOS mx/my/mz -> potential%mom
  ├─ mix potential%mom
  ├─ apply_constraints
  └─ calculate_moments: shared rotating-frame spin_density -> ql/gravity/LDM

k-space: H(k) -> eigenvectors/occupations
  ├─ calculate_band_moments: shared reciprocal spin_density -> band moments/ql
  ├─ compute_kspace_spin_moments_spinor: direct mx/my/mz -> potential%mom
  ├─ mix potential%mom
  ├─ apply_constraints
  └─ calculate_pl / EF / LDM / output
```

The shared `spin_density` object is real and active for radial/band moment products. It is not, in the current `self%run_dos` wiring, the sole producer of the moment that drives the SCF potential. That distinction matters for the frame-contract and “one density object is central” claims in the old WP7 report.

### 2.4 Frozen-magnon orchestration

`calculation.f90` provides two frozen-magnon branch modes:

```text
post_processing_frozen_magnon
  ├─ acoustic
  │    ├─ establish q=0 reference with gbt_single_q
  │    ├─ MFT: fixed reference, q-loop, canonical EBAND/force theorem
  │    └─ SCF: q-loop with self-consistent total energies
  └─ auto
       ├─ establish collinear per-sublattice reference angles
       ├─ choose/tilt one sublattice at a time
       ├─ rebuild GBT Hamiltonian for each probe
       └─ evaluate fixed-potential eband/RS energy and modes
```

The acoustic MFT path applies same-q `theta=0` subtraction as its gauge probe. The auto multi-sublattice path uses explicit per-type `theta_sublattice`/`phi_sublattice` values and is a force-theorem probe. Neither probe path updates a nonzero-q constraining field through a constrained SCF cycle.

## 3. B — representation, frame, and state map

| Object or quantity | Current meaning and producer | Frame/phase status | Evidence or caveat |
|---|---|---|---|
| `lattice%sbar` | Raw directed structure constants from `lattice_strux.f90`; orbital dimensions are allocated by the strux backend | No GBT phase is stored in this object; GBT reads it as immutable input | Current GBT source comments and `build_gbt_bulkham`; reverse-bond identity has historical oracle support but not a complete current production proof |
| `lattice%sdot` | Optional raw derivative structure constants for CCOR | Same raw-storage contract as `sbar`; GBT applies the endpoint link before CCOR contractions | `strux_want_sdot` is required for GBT CCOR; unsupported combinations are fatal |
| `q_ss` | Input q in Cartesian `2*pi/alat` units | Enters the GBT bond phase and lifecycle/BZ policy; explicit texture uses supplied site moments instead | Periodic NC rejects nonzero q rather than consuming it silently |
| `d_cart` / `alpha` | Directed bond vector from `clusba`, then `2*pi*q.dot(d)/alat` | The sign is directed and is part of the link | Exact sign and units are unit-tested historically; current production source has only a q=0 max-link diagnostic |
| `gbt_reference_frame` | SU(2) endpoint frame from theta/phi | Reference spin frame for each endpoint; not a final Hamiltonian rotation | `gbt_endpoint_angles` uses explicit per-type angles when present, otherwise up/down defaults and `potential%mom(3)` sign |
| `gbt_endpoint_link` | `Ua0† Rz(alpha) Ub0` | Carries the q-dependent relative phase between endpoint frames | This is the primitive GBT link used in `build_gbt_bulkham` |
| `gbt_lift_orbital_block` | Kronecker-like spinor lift of scalar orbital S | Applies one spin link to the orbital block in spin-major layout | Current helper is the only GBT orbital lifting route |
| `gbt_contract_collinear` | Contracts lifted S with endpoint `wx0 +/- sign*wx1` factors | Uses collinear endpoint response factors after the link | Ordinary LMTO contraction is retained; no post-hoc final-H rotation |
| `ee` | Directed gauged Hamiltonian bond block stored in spherical representation | Main primitive GBT product consumed by RS and k-space routes | Shared operator object across solvers; current exact equivalence between all consumers is not fully revalidated |
| `eecc` | Directed CCOR block from linked S/Sdot and CCOR contractions | Same endpoint link is used for S and Sdot | Supported only for the current two-centre/available Sdot slice; broader CCOR modes remain unavailable |
| `obarm` | Onsite overlap-like spinor from `potential%obx0/obx1` and full `potential%mom` | No translational GBT phase; local spin frame is inferred from the potential moment | Possible frame mismatch with `theta_sublattice`/`phi_sublattice` is an open risk that needs an explicit assertion/test |
| `enim` | Onsite energy-like spinor from `cx-cex` channel averages/differences and full `potential%mom` | No translational GBT phase | Same potential-moment/frame coupling caveat as `obarm` |
| `eeo` | `ee * obarm(target)` | Derived after the primitive GBT link; no second q phase in the real-space construction | HOH report supports this slice; generalized overlap remains guarded |
| `eeoee` | `eeo * ee†` same-bond diagnostic | Not a universal global HOH contraction | Source comment and old WP6A report explicitly limit its role |
| `potential%mom` | Normalized moment direction used by endpoint defaults, density axes, and SCF feedback | Semantically overloaded: it may be a current projected-DOS/eigenvector moment, density reference axis, or endpoint sign source | Current `self%run_dos` has direct RS/k-space moment producers separate from shared `spin_density` radial products |
| `potential%mom0` / `mom1` | Non-normalized zeroth/first-order moment channels | Used to seed constraint references when explicit references are absent and for magnetic observables | `mom0` is not interchangeable with the shared rotating-frame band density |
| `spin_density` | Full 2x2 spin density in an explicitly declared rotating frame | Has `axis`, `axis_set`, and density policy; supports `constrained_spiral` and `relaxed_reference` | Active for RS and k-space radial/band moment construction; not currently the only SCF moment source |
| `ql`, gravity centers, band moments | Radial/band-resolved products derived from the shared density object | Rotating-frame products, with lab reconstruction available | Historical WP7 contract tests are useful for this scope; full SCF centrality is not established |
| `mx,my,mz,mtot` | Magnetic moment outputs from projected DOS/eigenvector paths and related potential state | Treated as lab Cartesian quantities by the direct moment routines | Route and policy consistency needs a current cross-solver test |
| `constraint_reference` | Persistent per-record reference moment in `self` | Initialized from explicit `constraints_mom_ref` or `potential%mom0`; not automatically a q-dependent lab-frame reference | Current machinery is active, but reference-frame covariance at nonzero q is not established |
| `symbolic_atom%mag_cfield` | Per-site constraining field retained by `self`, passed to `constrain`, and inserted into the Hamiltonian | Ordinary path inserts it in `hmag`; GBT path inserts its Pauli block onsite with no translational bond phase | Current source disproves the old “field is discarded” claim; physical constrained-spiral semantics remain unvalidated |
| `constraint_energy` | `constrain` output retained by `self` and added to SCF energy bookkeeping | Controller/penalty energy is included in the current total-energy path | Inclusion is implemented; interpretation and cancellation in frozen-magnon comparisons are not established |

The most important state-contract finding is that “rotating-frame density,” “lab moment,” “endpoint frame,” and “constraint reference” are separate concepts in the source, but the current SCF loop still connects them through more than one moment producer. WP00 therefore does not treat a successful radial `ql` comparison as proof of a complete SCF frame contract.

## 8. Direct answers to the twelve WP00 questions

1. **Where does q enter?** It enters as `q_ss` from the Hamiltonian namelist, is converted into the directed bond phase in `gbt_endpoint_link`, and also controls reciprocal BZ/lifecycle policy. In explicit-texture mode the supplied site moments are the representation data; ordinary periodic NC rejects nonzero q.

2. **What are the endpoint frames?** `gbt_reference_frame` constructs the SU(2) endpoint frames. `gbt_endpoint_angles` selects explicit per-type theta/phi when supplied, otherwise the up/down collinear convention using the potential moment sign. `potential%mom` also serves as a density reference and SCF state, so it is not a single unambiguous synonym for every endpoint frame.

3. **Which structure constants are raw?** `lattice%sbar` and optional `lattice%sdot` are raw directed strux data. GBT reads them, constructs temporary linked/lifted blocks, and stores the contracted result in `ee`/`eecc`.

4. **How is the final Hamiltonian assembled?** `ee` and related blocks are consumed by the ordinary RS or ordinary reciprocal Fourier paths. There is no active final-Hamiltonian GBT rotation and no legacy `fourier_transform_gbt`.

5. **Is q=0 exact?** The primitive link has a q=0 identity diagnostic, and historical WP3/WP4/unit evidence supports exactness for the tested first-order slice. The current source does not itself prove equality to the ordinary path for every term, solver, frame, and SCF state; q=0 must be rerun as a current exact operator gate.

6. **Is the shifted-k identity exact?** WP1 independently tested the shifted-spinor/Stoner algebra. That is not the same as a current production matrix-level RS/k-space identity over all assembled terms. The latter remains open.

7. **Do RS and k-space consume the same operator?** They consume the same real-space `ee`/`eecc` data for supported bulk terms, with k-space using ordinary Fourier. Their numerical density/moment feedback paths are not fully identical, and historical convergence/mesh behavior remains a qualification risk.

8. **What is the density contract?** `spin_density` is a shared full 2x2 rotating-frame object with explicit axis and policy, and it drives radial/band moment products in both RS and k-space. Direct projected-DOS/eigenvector moment routines still update `potential%mom` in `self%run_dos`, so the complete SCF contract is mixed.

9. **What happens to constraints?** Current source persists a reference, passes `mag_cfield` to `constrain`, retains `constraint_energy`, and inserts the field into ordinary and GBT onsite Hamiltonian blocks. No current admissible test establishes nonzero-q constrained-spiral covariance, field-work cancellation, or constrained frozen-magnon energy semantics.

10. **Which feature combinations are supported?** Primitive S, selected HOH, selected CCOR, ordinary Fourier, RS/k-space bulk, MFT, SCF machinery, and current constraints have executable routes. GBT rejects active SOC, local-axis, Hubbard-V, generalized-overlap modes, and local/impurity Hamiltonian use; broader U, CCOR, and constrained-SCF claims remain conditional.

11. **What do frozen-magnon modes actually do?** Acoustic and auto branches exist. Acoustic MFT uses fixed-potential canonical EBAND with same-q theta-zero subtraction; acoustic SCF uses q-dependent self-consistent total energies. Auto tilts one sublattice at a time at fixed potential and evaluates force-theorem quantities. These are not a corrected constrained-MFT implementation.

12. **Which archived conclusions survive?** The primitive S/Sdot architecture, ordinary Fourier cleanup, q/BZ lifecycle, algebraic oracles, and selected HOH/CCOR slices survive. G7 must be narrowed to the tested radial/contract scope; the old inactive-constraint row is stale; G9 is not passed; G10 is cleanup only; VAL-16 current-state convergence and VAL-17 stiffness remain open.

## 9. WP00 conclusion and next gate

WP00 is complete as an archaeology and evidence map. It establishes the current implementation boundary and prevents the historical reports from being read as a blanket GBT qualification. No physics source was changed.

The next technically discriminating step is WP01 at the current HEAD: a minimal exact q=0/operator audit that compares ordinary and GBT blocks before diagonalization, separately records `S`, onsite, HOH, CCOR, and constraint contributions, and logs endpoint frames against `potential%mom` and the rotating-frame density axis. Only after that should the workflow promote current-head fixed-potential shifted-k and nonzero-q frame/constraint tests.
